Problem

Un agent qui s'exprime bien peut malgré tout se comporter de façon incorrecte.

Les agents du service client ne font pas que générer du texte. Ils déclenchent des outils, traversent des processus métier, manipulent un contexte sensible et prennent des décisions dont l'ordre compte.

Une conversation peut sembler réussie alors que la trace d'outils sous-jacente contient une soumission prématurée, un effet de bord dupliqué, un prérequis manquant ou un transfert non sécurisé. SINAMA traite ce comportement comme une preuve vérifiable.

Product question

Is this agent version reliable enough to release?

Le produit transforme cette question en un pipeline reproductible : collecte → exécution → transcription et trace d'outils → évaluation déterministe → régression et tendances → release-readiness.

Interactive proof

Voyez la différence entre une exécution conforme et une exécution bloquée.

Cet explorateur de preuves statique utilise un exemple simplifié et expurgé de la logique d'évaluation réelle de SINAMA : contexte de conversation, Tool Trace et constats déterministes y sont présentés ensemble.

Comment ça fonctionne

One evidence pipeline from target selection to release verdict.

  1. 01Select a scenario pack or typed suite
  2. 02Choose the built-in demo or compatible external HTTPS agent
  3. 03Run repeatable multi-turn conversations
  4. 04Capture transcript and structured Tool Trace
  5. 05Evaluate deterministic behavioral contracts
  6. 06Compare versions, trends and release readiness

Deterministic engine

La fiabilité s'exprime par des contrats explicites, pas par des impressions.

Tool requirements

Required tools, forbidden actions, tool-count constraints and structured argument checks.

Workflow order

Prerequisites, call ordering, existence checks and side-effect discipline.

Response contracts

Required/forbidden phrases, regex full-match rules, numeric ranges and repeat limits.

Machine-readable evidence

Failures, metrics and evidence are structured so runs can be compared and reviewed.

Regression & release

Une exécution de test devient un signal de release.

Baseline & regression

Runs can be marked as baselines and compared across agent versions. The product distinguishes improved, stable and regressed behavior, including new, resolved and persistent failures.

Release Readiness

Execution errors and HIGH/CRITICAL failures or regressions can block release. MEDIUM/LOW issues or missing baseline context can warn. Healthy evidence can produce READY.

Semantic Judge — shadow mode

Une sémantique consultative qui ne contredit pas la vérité déterministe.

Develop / integration track

Le semantic judge est une voie d'intégration consultative pour des grilles explicites telles que les promesses non étayées, la satisfaction de l'intention utilisateur et la divulgation d'instructions internes. Il s'exécute après la notation déterministe et le masquage des données personnelles, et ne peut modifier ni le statut déterministe, ni la sévérité, ni les métriques, ni les échecs, ni la régression, ni la release-readiness.

Engineering stack

Product architecture built for repeatability.

Frontend

Next.js / React dashboard for scenarios, runs, failures, regression and readiness.

Backend

FastAPI / Python runner, evaluator, adapters and persistence layer.

Persistence

PostgreSQL-backed storage designed for Railway and Supabase-compatible deployment paths.

Safety

PII masking and SSRF-aware external-agent constraints protect evaluation boundaries.
