Vue d'ensemble et problème

Rendre visible la pensée workflow par l'interaction.

Une expérience navigateur en production inspirée de n8n, qui montre la structure des flux de chatbot, la validation des nœuds, les chemins de fallback et la réflexion sur les parcours utilisateur.

Les workflows de chatbot sont difficiles à expliquer avec des schémas statiques seuls. AI Flow Puzzle transforme déclencheurs, chemins d'intention, branchements, réponses, sécurité de fallback et étapes d'automatisation en une expérience navigateur interactive.

Le projet est conçu comme une démonstration de portfolio, pas comme une plateforme de chatbot en production. Les différentes structures de workflow se construisent, s'inspectent, se valident et se simulent directement dans le navigateur.

J'ai conçu les scénarios, le vocabulaire des nœuds, les chemins de workflow requis, les règles de validation, l'interface bilingue et l'implémentation côté navigateur. Le projet associe la pensée des flux conversationnels à la conception d'interaction frontend.

Interaction et système de nœuds

Un plateau de workflow configurable bâti autour de groupes fonctionnels clairs.

Les utilisateurs choisissent un scénario, ajoutent des nœuds depuis une palette, les positionnent au pointeur et relient une source à une cible. Des courbes de Bézier en SVG visualisent le graphe, tandis que les modèles Plateau vide, Happy path et Solution complète offrent différents points de départ.

Entrée

Chat Trigger · Intent Detector

Logique

Condition · Route Switch

Connaissance / raisonnement

Knowledge Base · LLM Reasoning

Automatisation

Google Sheets · CRM Update · Email Notify

Sécurité

Fallback · Human Handoff

Sortie

Response · End

L'exécution simulée, le journal d'exécution, les indices, la réinitialisation et l'import/export JSON rendent la structure inspectable. Les nœuds représentent des concepts de workflow et n'appellent aucun service externe.

LLM Reasoning représente une étape de raisonnement conceptuelle dans le workflow ; aucun appel réel à un LLM n'est effectué.

Validation et notation

Un retour fondé sur des règles, avec des limites explicites.

Un système de validation fondé sur des règles, côté navigateur, vérifie les types de nœuds requis et les connexions requises entre types. Les nœuds et connexions manquants sont signalés, et les liens dupliqués ou vers soi-même sont empêchés.

Les flux réussis comme incomplets reçoivent un retour simulé sur la logique, l'automatisation, l'UX, la sécurité et l'efficacité.

  • Logic
  • Automation
  • UX
  • Safety
  • Efficiency

Limites actuelles

  • Il ne s'agit pas d'une validation sémantique complète du graphe.
  • Certaines connexions supplémentaires n'invalident pas forcément un flux.
  • Des cycles peuvent être créés, même si l'exécution évite les répétitions infinies.
  • L'exécution est simulée et ne s'appuie sur aucun backend.
  • Le comportement de fallback ne repose pas sur un véritable score de confiance.

Mise en œuvre technique

APIs navigateur natives, état explicite et exports portables.

L'application conserve scénarios, nœuds, liens, sélection, validation et statut d'exécution dans un état navigateur encapsulé dans une closure. Les nœuds sont positionnés en pourcentages et les connexions rendues sous forme de courbes de Bézier SVG entre éléments du DOM.

L'import/export JSON comprend le scénario, les nœuds, la configuration, les coordonnées, les connexions et le résumé de qualité. Canvas, FileReader, les téléchargements Blob, le presse-papiers et le Local Storage apportent des outils navigateur complémentaires.

  • HTML5
  • CSS3
  • Vanilla JavaScript
  • DOM APIs
  • Pointer Events
  • SVG Paths
  • Canvas API
  • JSON Serialization
  • FileReader
  • Blob Downloads
  • Clipboard API
  • Le Local Storage n'est utilisé que pour le score.
  • Design responsive
  • Inter
  • Boxicons

Tests, itération et limites

Conçu pour une exploration répétée, quels que soient le mode de saisie et la taille d'écran.

Les retours sur les flux incomplets, les modèles, les indices, la réinitialisation et la validation répétée permettent d'itérer sans quitter la page. L'interface prend en charge EN/TR, les thèmes clair et sombre, des points de rupture responsive et l'interaction à la souris comme au toucher.

Les nœuds peuvent être sélectionnés et supprimés au clavier, mais leur position sur le plateau n'est pas modifiable au clavier pour l'instant.

Les workflows denses restent utilisables, mais demandent un positionnement plus soigné sur petits écrans.
