Problem

A fluent agent can still behave incorrectly.

Customer-service agents do more than generate text. They trigger tools, move through business workflows, handle sensitive context and make decisions whose order matters.

A conversation may look successful while the underlying tool trace contains a premature submission, duplicate side effect, missing prerequisite or unsafe handoff. SINAMA treats that behavior as testable evidence.

Product question

Is this agent version reliable enough to release?

The product turns that question into a repeatable pipeline: collection → execution → transcript/tool trace → deterministic evaluation → regression/trends → release readiness.

How it works

One evidence pipeline from target selection to release verdict.

  1. 01Select a scenario pack or typed suite
  2. 02Choose the built-in demo or compatible external HTTPS agent
  3. 03Run repeatable multi-turn conversations
  4. 04Capture transcript and structured Tool Trace
  5. 05Evaluate deterministic behavioral contracts
  6. 06Compare versions, trends and release readiness

Deterministic engine

Reliability is expressed as explicit contracts, not vibes.

Tool requirements

Required tools, forbidden actions, tool-count constraints and structured argument checks.

Workflow order

Prerequisites, call ordering, existence checks and side-effect discipline.

Response contracts

Required/forbidden phrases, regex full-match rules, numeric ranges and repeat limits.

Machine-readable evidence

Failures, metrics and evidence are structured so runs can be compared and reviewed.

Regression & release

A test run becomes a release signal.

Baseline & regression

Runs can be marked as baselines and compared across agent versions. The product distinguishes improved, stable and regressed behavior, including new, resolved and persistent failures.

Release Readiness

Execution errors and HIGH/CRITICAL failures or regressions can block release. MEDIUM/LOW issues or missing baseline context can warn. Healthy evidence can produce READY.

Semantic Judge — shadow mode

Advisory semantics without overriding deterministic truth.

Develop / integration track

The semantic judge is an advisory integration track for explicit rubrics such as unsupported promises, user-intent satisfaction and internal-instruction disclosure. It runs after deterministic scoring and PII masking, and it cannot change deterministic status, severity, metrics, failures, regression or readiness.
