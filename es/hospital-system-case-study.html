Hospital System

Una aplicación de Windows Forms para varios roles construida con C#, .NET Framework y SQL Server que muestra el registro de pacientes, la programación de citas y los flujos del personal hospitalario. El repositorio conserva extractos de código, un esquema de base de datos y evidencia de la interfaz de la compilación académica original de 2024.

Contexto del proyecto

Construir un flujo de escritorio respaldado por base de datos alrededor de tres roles de usuario.

El proyecto se creó como trabajo individual de la asignatura de Programación Visual, centrado en registro, inicio de sesión y operaciones CRUD respaldados por base de datos. Su dominio se modeló alrededor de un flujo de citas simplificado para pacientes, médicos y secretaría, no de un entorno hospitalario en producción.

El repositorio conserva 17 extractos de código, un esquema de base de datos y evidencia de la interfaz, pero no los archivos originales de solución, proyecto, Designer, recursos o compilación. Se presenta como archivo de código fuente, no como producto ejecutable o desplegado.

Roles de usuario

Tres flujos propios basados en formularios

Los recorridos de paciente, médico y secretaría se separan mediante formularios propios y comprobaciones de credenciales en base de datos.

Paciente

Registro, comprobación de credenciales en base de datos, edición de perfil, selección de especialidad y médico, filtrado de franjas disponibles, reserva de cita y consulta del listado de citas.

Secretaría

Comprobación de credenciales en base de datos, creación de franjas de cita, gestión de médicos, gestión de especialidades, creación de avisos y acceso completo al listado de citas.

Médico

Comprobación de credenciales en base de datos, información de perfil, listado de citas asignadas, consulta del detalle del motivo, acceso a avisos y edición de perfil.

La separación se implementa mediante formularios propios y comprobaciones de credenciales, no mediante un marco centralizado de autorización por roles.

Diseño de la base de datos

Seis tablas de SQL Server que soportan operaciones directas entre formulario y base de datos.

El modelo de SQL Server contiene seis tablas que cubren pacientes, médicos, secretaría, especialidades, citas y avisos. Los formularios acceden a estas tablas directamente mediante comandos y adaptadores ADO.NET, y las relaciones de cita se representan principalmente mediante valores de TC, nombre de médico y nombre de especialidad.

Avisos

Límites verificados

  • Los valores de fecha y hora se almacenan como cadenas de texto.
  • Las relaciones de médico y especialidad se almacenan como texto.
  • La asociación del paciente utiliza una cadena TC.
  • En el esquema archivado no hay restricciones PK/FK/unique/check.
  • RandevuDurum tiene el valor por defecto 0.

Implementación en Windows Forms

Quince formularios que combinan interfaz basada en eventos y operaciones ADO.NET.

Quince formularios de cara al usuario cubren navegación, registro, inicio de sesión, edición de perfil, operaciones de citas y administración de secretaría. La implementación muestra desarrollo WinForms basado en eventos, enlace de DataGridView y comandos SQL mayoritariamente parametrizados.

Evidencia de la implementación

  • Form navigation
  • DataGridView
  • SqlConnection

  • Parameterized commands
  • MessageBox feedback
  • Direct CRUD operations

Pruebas y limitaciones

Evidencia útil de flujos con límites archivísticos y técnicos claros.

El código archivado incluye comprobaciones de campos obligatorios y mensajes de éxito o error de cara al usuario en varios formularios. La verificación en ejecución está bloqueada actualmente porque el repositorio no incluye los archivos originales de solución, proyecto, Designer o recursos, y la implementación tampoco cuenta con capas de transacciones, gestión de excepciones ni tratamiento seguro de contraseñas.

Verificado en el archivo

  • Comprobaciones de campos obligatorios en varios formularios
  • Mensajes de éxito y error de cara al usuario
  • Comprobaciones de credenciales respaldadas por base de datos
  • Comandos parametrizados en la mayoría de las operaciones de escritura
  • Extractos de código de CRUD y del flujo de citas

Limitaciones

  • El repositorio es un archivo de código fuente, no una compilación ejecutable.
  • Los archivos originales de solución y Designer no están disponibles.
  • En la implementación archivada las contraseñas se almacenan y comparan en texto plano.
  • No existe una capa centralizada de autorización.
  • Algunos filtros SQL utilizan concatenación de cadenas.
  • La gestión del ciclo de vida de la conexión es incompleta.
  • No se han implementado la gestión de excepciones ni las transacciones.
  • No se han implementado la cancelación ni la reprogramación de citas.
  • Las restricciones y relaciones de la base de datos son limitadas.
  • El comportamiento en ejecución no se puede reverificar actualmente desde este repositorio.

El proyecto muestra flujos de escritorio específicos por rol y comprobaciones de credenciales respaldadas por base de datos, mientras que la seguridad de contraseñas, la autorización y los controles de privacidad quedan fuera del alcance completado.

Un flujo de escritorio para varios roles conservado como evidencia técnica del proyecto.

El proyecto muestra un flujo de escritorio de extremo a extremo que abarca varios roles de usuario, navegación entre formularios y operaciones sobre datos relacionales. Su principal valor de portafolio es la combinación de lógica de interfaz en C#, acceso ADO.NET y un dominio de citas concreto, mientras que la galería conserva evidencia de la interfaz original respetuosa con la privacidad.
