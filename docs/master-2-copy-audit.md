# Master 2 copy audit

## Method

Public copy was reviewed from the authored English route documents, canonical portfolio JSON, case-study data, and dynamic UI sources. Generated locale documents and legacy compatibility stubs are outputs and were not treated as independent copy owners.

The review labels copy as fact, evidence, explanation, positioning, CTA, navigation, redundant, vague, outdated, unsupported, or overly AI-sounding. Canonical data remains the source for project facts; editorial pages may summarize it but do not create new outcomes.

## Decisions

- Primary positioning: **Forward Deployed Engineer**.
- Supporting background: **AI Designer + Software Developer**.
- Supporting capabilities: discovery, technical scoping, prototyping, integration, evaluation, hardening, and delivery.
- Strongest evidence order: SINAMA, AI Chatbot Flow Design, Atölye Joyday; broader product/software work follows.
- “Proves”, “demonstrates”, and “showcases” are removed from repeated card prose where the adjacent evidence can carry the point.
- Result/impact labels are used only where the canonical record establishes a result. Archive projects use evidence, implementation, or current status instead.
- Request copy describes transport honestly and never claims server confirmation.
- Product names, employers, framework names, routes, years, and technology facts are not translated or duplicated into editorial sources.

## Surface disposition

| Surface group | Classification outcome | Action |
| --- | --- | --- |
| Home | Positioning was strong; biography and “proof” explanation repeated | Shortened hero, promoted evidence, removed redundant proof language |
| Works | Evidence tiers were strong; many cards began with “Proves” | Kept tier model, rewrote primary summaries as factual scope statements |
| About | Background/evidence were valid; opening repeated Home | Reframed around working approach and current direction |
| Case studies | Mostly evidence/fact; some headings implied outcomes | Preserved concrete details, standardized labels, avoided unsupported outcome upgrades |
| Experience / Now | Factual timeline and current-work explanation | Retained, tightened visually rather than manufacturing new claims |
| Games / Labs | Clear breadth/experiment purpose | Retained and visually subordinated to flagship professional work |
| Project detail | Canonical data is authoritative; generic “ability” language was vague | Use project status, implementation, evidence, and lessons language |
| Request | Honest transport explanation | Retained; form becomes the visual priority |
| 404 / Privacy / Certificates | Functional and factual | Polished within shared system; no marketing expansion |
| Recruiter / Command | Navigation and evidence utility | Behavior retained; no new role-fit claims |

## Factual conflicts

No blocking factual conflict was found. Where page copy was broader than canonical evidence, the copy was narrowed. No metric, customer result, revenue, user count, ownership claim, or performance gain was introduced.

## Multilingual quality

Rewritten stable-key copy is owned in EN/TR/DE/ES/FR message catalogs. Translations preserve the same role, evidence order, and CTA intent while allowing natural sentence structure. Protected product/framework names remain unchanged. Layout acceptance includes German expansion, French/Spanish accents, and Turkish casing.
