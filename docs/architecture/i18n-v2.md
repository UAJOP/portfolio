# i18n V2 architecture

## Authorities

- `data/i18n/locales.json`: active locale and localized-route gate
- `data/site/routes.json`: the only route map
- `data/i18n/message-contract.json`: message domain and fallback policy
- `data/i18n/messages/<locale>/common.json`: production shared UI messages with stable semantic keys
- `data/i18n/messages/{en,tr}/react-preview.json`: development-only React preview messages
- `data/i18n/formatting.json`: `Intl` locale tags
- `data/i18n/glossary.json`: protected product, technology, role, and reviewed language-neutral terms

English remains unprefixed. Turkish, German, Spanish, and French use `/tr/`, `/de/`, `/es/`, and `/fr/`. Language switching uses the clean-route registry and preserves allowed query/hash state; i18n owns no route table.

## Message models

New shared UI copy uses stable semantic keys such as `language.selectorLabel` and `theme.switchToDark`. Every production locale has the same key set, non-empty values, and matching interpolation placeholders. Production fallback is forbidden by blocking QA; development fallback displays the key so drift is visible.

Metadata, project copy, canonical content, case-study copy, and runtime feature copy already use stable route IDs, project slugs, registry paths, feature namespaces, and field paths. Those stable domains remain in their existing files to avoid a risky copy rewrite.

Historical static-page text is the one explicit compatibility domain. It is keyed by its English phrase under locale `pages.json` packs because the legacy HTML predates semantic message IDs. It remains complete across all five locales, and its current 1,043-key set is hash-pinned so new phrase keys fail QA. Page-by-page migration to semantic keys belongs with the Master 2 content/component migration; retaining this bounded adapter avoids changing public copy during the foundation phase.

## Completeness and correctness

`qa:i18n` blocks missing, stale, or empty production common-message keys; placeholder mismatch and invalid interpolation; incomplete active-locale coverage; unreviewed English leakage; malformed metadata; missing locale documents; stale generated output; and route/canonical/hreflang/sitemap mismatch.

Locale-aware date, number, and plural primitives live in `js/core/i18n-format.js` and use `Intl.DateTimeFormat`, `Intl.NumberFormat`, and `Intl.PluralRules` with the reviewed tags in `formatting.json`. Features should pass structured values to these helpers rather than concatenate English grammar.

## Editing flow

1. Edit canonical facts only in `data/portfolio/`.
2. Edit shared production UI in each locale's `messages/<locale>/common.json`.
3. Edit structured translations in the matching stable domain pack/source.
4. Use the glossary for intentionally unchanged terms; do not bypass leakage checks ad hoc.
5. Run explicit generation when a committed artifact changes.
6. Run `npm run qa:i18n`; do not regenerate from QA.
